# Customer Shopping Behavior Analysis

## 📌 Project Overview

This project analyzes customer shopping behavior using **Python, SQL,
and Power BI** to identify purchasing patterns, revenue drivers, product
performance, discount behavior, subscription trends, and customer
segments.

The objective is to turn raw customer transaction data into business
insights that can support decisions around **sales growth, customer
retention, product strategy, and discount optimization**.

------------------------------------------------------------------------

## 🎯 Business Questions

The analysis answers the following questions:

1.  What is the total revenue generated by male vs. female customers?
2.  Which customers used a discount but still spent more than the
    average purchase amount?
3.  Which are the top 5 products with the highest average review rating?
4.  How do average purchase amounts compare between Standard and Express
    Shipping?
5.  Do subscribed customers spend more than non-subscribers?
6.  Which 5 products have the highest percentage of purchases with
    discounts?
7.  How can customers be segmented into New, Returning, and Loyal
    customers?
8.  What are the top 3 most purchased products within each category?
9.  Are customers with more than 5 previous purchases also likely to
    subscribe?
10. What is the revenue contribution of each age group?

## 📊 Dataset

-   **3,900 customer purchase records**
-   **18 original columns**
-   Age range: **18--70**
-   Average purchase amount: **\$59.76**
-   **25 products**
-   **4 product categories**
-   **50 locations**
-   37 missing review ratings were handled using category-level median

The dataset contains customer, product, purchase, review, discount,
subscription, shipping and previous-purchase information.

## 🔄 Data Preparation

The data preparation workflow included:

1.  Loading the CSV dataset using Pandas.
2.  Inspecting data types, statistics and missing values.
3.  Handling missing review ratings using category-level median values.
4.  Standardizing column names to lowercase `snake_case`.
5.  Renaming `purchase_amount_(usd)` to `purchase_amount`.
6.  Creating an `age_group` field.
7.  Converting purchase-frequency labels into day-based values.
8.  Removing `promo_code_used` because it duplicated the information
    represented by `discount_applied`.
9.  Loading the prepared dataset into PostgreSQL for SQL analysis.

## 💰 How the Analysis Can Support Sales Growth

### 1. Increase basket value

Use high-revenue products to create product bundles and cross-selling
opportunities.

Example:

> High-performing clothing item + complementary product

Measure the change in **Average Order Value (AOV)** before and after
introducing bundles.

### 2. Improve repeat purchases

Use:

-   `previous_purchases`
-   Purchase frequency
-   Customer segment

to identify customers who may be approaching their next expected
purchase cycle.

### 3. Optimize discounts

The dashboard shows that a large share of purchases did not use a
discount.

Instead of applying discounts broadly, analyze whether discounts
generate enough additional revenue to justify their cost.

### 4. Improve subscription conversion

Compare:

-   Average spend
-   Total revenue
-   Number of purchases
-   Previous purchases

between subscribers and non-subscribers.

### 5. Cross-sell by category

Use product rankings within each category to identify frequently
purchased products and create category-based recommendations.

### 6. Monitor product revenue

Track:

-   Revenue
-   Order volume
-   Average purchase amount

at product level to distinguish high-volume products from high-value
products.

## 🔁 Return Order Analysis

### Important limitation

The current dataset does **not contain return-order information**.

There is no:

-   `return_status`
-   Return date
-   Return reason
-   Refund amount
-   Return quantity
-   Order-level return identifier

Therefore, the current dataset cannot be used to calculate the actual
return rate or identify which products are causing returns.

### Data required for return analysis

A future version of the dataset should include:

  Field             Purpose
  ----------------- ---------------------------------------
  Order ID          Link purchase and return records
  Return Status     Identify returned orders
  Return Reason     Understand why orders are returned
  Return Date       Analyze return timing
  Delivery Date     Calculate delivery-to-return duration
  Return Quantity   Measure returned units
  Refund Amount     Measure financial impact

Once available, return rate can be analyzed by:

-   Product
-   Category
-   Size
-   Shipping type
-   Payment method
-   Location
-   Season
-   Customer segment

This would allow the business to identify the main return drivers and
test targeted improvements.
